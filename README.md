# 🩺 Dashboard ผลวัดความดัน พนักงานขับรถ (TPT)

Dashboard แสดงผลการวัดความดันโลหิตและชีพจรของ พขร. กะ A / B
- **ภาพรวม**: KPI, กราฟจำนวนคนที่ความดันสูงรายวัน, ค่าเฉลี่ยทั้งกลุ่ม, ตารางสรุปรายบุคคล และตารางสีรายวัน
- **ค้นหา**: พิมพ์ชื่อ หรือทะเบียนรถ (เช่น `สมชาย`, `71-3416` หรือ `3416`) ในช่องค้นหา — ตาราง/กราฟภาพรวมจะกรองตามทันที กด Enter หรือคลิกรายชื่อเพื่อเปิดหน้ารายบุคคล
- **รายบุคคล**: เลือกจากช่องค้นหา (หรือคลิกชื่อในตาราง) เพื่อดูกราฟแนวโน้มความดัน ชีพจร และบันทึกรายวัน
- กรองตามกะได้ (ทั้งหมด / A / B) · รองรับมือถือ และโหมดมืด

- หน้าเว็บโหลดข้อมูลใหม่เองทุก 5 นาที (ไม่ต้องกดรีเฟรช)
- **📥 ดึงข้อมูล / ออกรายงาน** (แท็บที่ 4): เลือกรูปแบบ (รายการวัดทุกครั้ง · สรุปรายบุคคล · สรุปตามประเภท/กะ · สรุปรายวัน) และเงื่อนไข (ประเภท, กะ, ช่วงวันที่, เช้า/บ่าย, พนักงาน, เฉพาะที่เกินเกณฑ์ ฯลฯ) ดูตัวอย่าง แล้วดาวน์โหลด **Excel / CSV** หรือ **พิมพ์ / PDF** · วันที่ทั้งหมดในแท็บนี้เป็น DD/MM/YYYY · ดาวน์โหลด **ไฟล์ Excel ต้นฉบับ** ได้ท้ายแท็บ · มีปุ่มรายงานสำเร็จรูป เช่น "สรุปรายบุคคล TPT", "สรุปรายกะ", "พบแพทย์ / งดขับ"
- **อัปเดตหน้าเว็บอัตโนมัติ**: เมื่อมีการแก้หน้าเว็บ (deploy เวอร์ชันใหม่) ทุกเครื่องที่เปิด Dashboard ค้างไว้จะขึ้น "มีเวอร์ชันใหม่ — กำลังอัปเดต…" แล้วรีโหลดเองภายใน ~5 นาที (หรือทันทีเมื่อกลับมาที่แท็บ) · ข้อมูลใหม่จาก Excel ยังรีเฟรชแบบเดิมโดยไม่รีโหลดหน้า · เวอร์ชันดูได้ท้ายหน้า
- **👥 กำลังดูอยู่ X คน**: ใต้หัวข้อ แสดงจำนวนเบราว์เซอร์ที่เปิด Dashboard อยู่ตอนนี้ (1 เบราว์เซอร์ = 1 คน ไม่เก็บชื่อ) ผ่าน Firebase Realtime Database — อัปเดตทันทีเมื่อมีคนเข้า/ออก (ดูวิธีตั้งค่าด้านล่าง)
- **แจ้งเตือน "ต้องติดตาม"**: กล่องด้านบนสุดแสดง พขร. ที่ผลวัดวันล่าสุด **เกินเกณฑ์ขับ (≥140/90)** พร้อมวิธีปฏิบัติ (เรียง สูงมาก/งดขับ ก่อน) เลือกดูวันก่อนหน้าได้ · ปุ่ม 🔔 แสดงจำนวน และชื่อแท็บเบราว์เซอร์ขึ้นตัวเลข เช่น `(3) Dashboard…`
  - รายการที่เข้ามาใหม่ตั้งแต่เปิดดูครั้งก่อนจะมีป้าย **ใหม่** และกล่องจะกะพริบ
  - กด **🔔 เปิดการแจ้งเตือนบนเครื่องนี้** เพื่อให้เบราว์เซอร์เด้งแจ้งเตือนเมื่อมีผลเกินเกณฑ์ใหม่ (ต้องเปิดหน้า Dashboard ทิ้งไว้ ย่อได้)

## เกณฑ์ระดับความดัน (รพ.ศิริราชปิยมหาราชการุณย์ / WHO)
ใช้ระดับที่ **สูงกว่า** ระหว่างค่าบน (SYS) และค่าล่าง (DIA) · พขร. ขับรถได้เมื่อ **ไม่เกิน 140/90**

| ระดับ | SYS | DIA | วิธีปฏิบัติ |
|---|---|---|---|
| ความดันต่ำ | < 90 | < 60 | ขับได้ถ้าไม่มีอาการร่วม หากหน้ามืด ตาลาย ใจสั่น เป็นลม → **งดขับรถ** |
| ความดันที่ดี | < 120 | < 80 | ขับรถได้ตามปกติ |
| ปกติ | 120–129 | 80–84 | ขับได้ บันทึกและติดตามความดันสม่ำเสมอ |
| ค่อนข้างสูง | 130–139 | 85–89 | ขับได้ (ไม่เกิน 140/90) และติดตามสม่ำเสมอ |
| สูงเล็กน้อย | 140–159 | 90–99 | นั่งพัก ≥ 5 นาที วัดซ้ำ หากยังสูงแจ้งผู้รับผิดชอบ |
| สูงปานกลาง | 160–179 | 100–109 | พักและวัดซ้ำ หากยังสูง ส่งแพทย์ประเมินก่อนกลับไปขับ |
| สูงมาก | ≥ 180 | ≥ 110 | **งดขับรถ** ส่งประเมินทางการแพทย์ |

แก้เกณฑ์ได้ที่ตัวแปร `LEVELS` และฟังก์ชัน `levelOf` ใน `site/index.html`

## เปิดใช้งานบน GitHub Pages (ทำครั้งแรกครั้งเดียว)
1. Merge โค้ดเข้า branch `main`
2. ไปที่ **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
3. ไปที่แท็บ **Actions** → เลือก *Build & Deploy Dashboard* → **Run workflow** (หรือ push อะไรก็ได้เข้า main)
4. เมื่อเสร็จ จะได้ลิงก์ `https://<user>.github.io/<repo>/`

> ⚠️ ข้อมูลมีชื่อ-สกุลและข้อมูลสุขภาพ — GitHub Pages ของ repo สาธารณะ **ทุกคนเปิดดูได้**
> ถ้าต้องการจำกัดผู้ดู ให้ตั้ง repo เป็น Private (Pages แบบจำกัดสิทธิ์ต้องใช้ GitHub Enterprise) หรือเปิดใช้ภายในองค์กรแทน

## ตั้งค่าตัวนับ "กำลังดูอยู่" (Firebase)
ใช้ **Realtime Database** ของโปรเจกต์ `test-stock-78d08` (ค่าอยู่ใน `site/firebase-config.js` แล้ว)
ฐานข้อมูลนี้ **ใช้ร่วมกับแอปอื่น (5ส: `stats`, `presence`, `rosterHistory5s`)** — Dashboard เก็บแยกที่ `bp-dashboard/presence`

**Rules:** [Realtime Database → Rules](https://console.firebase.google.com/project/test-stock-78d08/database/test-stock-78d08-default-rtdb/rules)
⚠️ **ห้ามลบ rules เดิม** — ให้ **เพิ่ม** ส่วน `bp-dashboard` เป็นพี่น้องกับส่วนอื่นภายใน `"rules": { ... }` แล้วกด Publish
```json
"bp-dashboard": {
  "presence": {
    ".read": true,
    "$browser": {
      ".validate": "$browser.length <= 32",
      "$tab": {
        ".write": true,
        ".validate": "$tab.length <= 16 && newData.isNumber() && newData.val() <= now + 60000"
      }
    }
  }
}
```
(อนุญาตให้เขียนได้เฉพาะเวลาสั้น ๆ ใน `bp-dashboard/presence/<browser>/<tab>` เท่านั้น ส่วนอื่นของฐานข้อมูลไม่เปลี่ยน)

ถ้าตั้ง `window.BP_FIREBASE_CONFIG = null` ใน `site/firebase-config.js` ตัวนับจะซ่อนไป ส่วนอื่นใช้งานได้ปกติ

## หลายเดือน / การติดตามผล
- **ตัวเลือกเดือน** (แถบตัวกรอง): ค่าเริ่มต้น = เดือนล่าสุด · ตัวเลข "ทั้งเดือน" กราฟ ตารางสี รายชื่อ และแท็บดึงข้อมูล เป็นของเดือนที่เลือก · มี "ทุกเดือน (รวม)" · เดือนใหม่เข้ามาระหว่างเปิดหน้าค้าง → เลื่อนไปเดือนใหม่ให้เอง
  หน้ารายบุคคลแสดง **ค่าเฉลี่ยเดือนก่อน** พร้อมลูกศรเทียบ · เดือนใหม่จะเพิ่มเป็นไฟล์ใหม่หรือชีตใหม่ก็ได้ (หัวตารางต้องบอกเดือน เช่น `วันที่ 1-31 /12/26`)
- **เตือนข้อมูลไม่อัปเดต**: ไม่มีผลวัดใหม่ ≥ 2 วันทำงาน (จ.–ส.) → แถบเหลืองใต้หัวเว็บ (ตรวจการลงข้อมูล / เครื่องที่รัน auto-sync.bat)
- **แถบ "ต้องติดตาม"** บอก "ติดตามแล้ว X · ยังไม่มีการติดตาม Y" (ติดตามแล้ว = มีหมายเหตุภายใน 30 วัน) และกดดูเฉพาะคนที่ยังไม่ติดตามได้
- **การ์ด "📅 นัดพบแพทย์"**: จากหมายเหตุล่าสุดแบบ "รอพบแพทย์ตามใบนัด" — เลยวันนัดแล้ว (แดง) และนัดภายใน 7 วัน
- **รายงาน "ประวัติการติดตาม (หมายเหตุ)"** ในแท็บดึงข้อมูล: ทุกหมายเหตุ + สถานะ/วันนัด/ผู้บันทึก (Excel / CSV / พิมพ์)
- หน้าเว็บมี `<meta name="robots" content="noindex">` ขอไม่ให้ Google เก็บ — **ไม่ได้ทำให้เป็นความลับ** ใครมีลิงก์ยังเปิดได้

## หมายเหตุ / การติดตาม รายบุคคล (Firebase)
ในหน้ารายบุคคลมีการ์ด **📝 หมายเหตุ / การติดตาม** — บันทึกครั้งเดียว ใช้ต่อได้ทุกเดือน (ผูกกับ ประเภท + ชื่อ ไม่ผูกกับเดือน)
- สถานะสำเร็จรูป: 💊 รักษาแล้ว · ทานยาความดันอยู่ / 📅 รอพบแพทย์ตามใบนัด (มีช่องวันนัด — เลยวันนัดจะขึ้นสีแดง) / 🏥 พบแพทย์แล้ว · ให้ติดตามอาการ / 🗣️ แจ้งให้ไปพบแพทย์แล้ว / 🔁 วัดซ้ำแล้ว ค่ากลับมาปกติ / 📝 อื่นๆ (ระบุเอง)
- แนบภาพได้สูงสุด 4 ภาพ (ใบนัด, ซองยา ฯลฯ) — ย่อเป็น JPEG ไม่เกิน ~480 KB ต่อภาพแล้วเก็บใน Realtime Database (Firebase Storage ต้องใช้แพลนเสียเงิน จึงไม่ใช้)
- **ทุกคนดูได้** (ข้อความ + ภาพ) · **เพิ่ม / แก้ / ลบ ได้เฉพาะบัญชีที่ผู้ดูแลให้สิทธิ์**
- หมายเหตุล่าสุดแสดงเป็นป้ายในตารางรายชื่อ, แถบ "ต้องติดตาม" และคอลัมน์ "หมายเหตุล่าสุด" ในรายงานสรุปรายบุคคล

### ตั้งค่าครั้งแรก (ผู้ดูแล)
1. **เปิดล็อกอินแบบอีเมล:** [Firebase Console → Authentication → Sign-in method](https://console.firebase.google.com/project/test-stock-78d08/authentication/providers) → เปิด **Email/Password** (ถ้ายังไม่เปิด)
2. **สร้างบัญชีคนที่บันทึกได้:** Authentication → Users → **Add user** (อีเมล + รหัสผ่าน) → คัดลอก **User UID**
3. **ให้สิทธิ์:** [Realtime Database → Data](https://console.firebase.google.com/project/test-stock-78d08/database/test-stock-78d08-default-rtdb/data) → ที่ `bp-dashboard` กด ＋ เพิ่ม `editors` → ภายในเพิ่ม key = UID, value = `true`
   (คนที่ล็อกอินแต่ยังไม่มีสิทธิ์ หน้าเว็บจะแสดง UID ให้ส่งมาให้ผู้ดูแล)
4. **Rules:** แทนที่ส่วน `"bp-dashboard": { ... }` เดิมด้วยชุดนี้ (⚠️ ห้ามแตะส่วนอื่นของ 5ส) แล้ว Publish
```json
"bp-dashboard": {
  "presence": {
    ".read": true,
    "$browser": {
      ".validate": "$browser.length <= 32",
      "$tab": {
        ".write": true,
        ".validate": "$tab.length <= 16 && newData.isNumber() && newData.val() <= now + 60000"
      }
    }
  },
  "editors": {
    "$uid": { ".read": "auth != null && auth.uid === $uid" }
  },
  "notes": {
    ".read": true,
    "$person": {
      ".validate": "$person.length <= 120",
      "$note": {
        ".write": "auth != null && root.child('bp-dashboard/editors').child(auth.uid).val() === true",
        ".validate": "newData.hasChildren(['kind', 'date', 'byUid', 'at']) && newData.child('kind').isString() && newData.child('kind').val().length <= 20 && newData.child('date').isString() && newData.child('date').val().matches(/^\\d{4}-\\d{2}-\\d{2}$/) && (!newData.child('text').exists() || (newData.child('text').isString() && newData.child('text').val().length <= 1000)) && (!newData.child('appt').exists() || (newData.child('appt').isString() && newData.child('appt').val().matches(/^\\d{4}-\\d{2}-\\d{2}$/)))"
      }
    }
  },
  "noteImages": {
    ".read": true,
    "$person": {
      "$note": {
        ".write": "auth != null && root.child('bp-dashboard/editors').child(auth.uid).val() === true",
        "$img": {
          ".validate": "$img.matches(/^i[0-3]$/) && newData.isString() && newData.val().beginsWith('data:image/') && newData.val().length <= 700000"
        }
      }
    }
  }
}
```
- ใครสมัครบัญชีเองได้ก็ **บันทึกไม่ได้** ถ้า UID ไม่อยู่ใน `bp-dashboard/editors` (Rules ตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม)
- ⚠️ ข้อความและภาพแนบ **ทุกคนที่มีลิงก์เว็บเปิดดูได้** (ตามที่เลือกไว้) — แนบเฉพาะสิ่งที่จำเป็น
- พื้นที่ฟรีของ Realtime Database = 1 GB (ภาพละ ~0.1–0.5 MB → หลายพันภาพ)

## อัปเดตข้อมูล
1. บันทึกไฟล์ Excel ตามรูปแบบเดิม (ชื่อพนักงานขับรถ | ทะเบียนรถ | กะ | … | `วันที่ 1-30 /11/26` → บน / ล่าง / ชีพจร)
2. อัปโหลดไฟล์ไปที่โฟลเดอร์ `data/` (Add file → Upload files) — แทนที่ไฟล์เดิม หรือเพิ่มไฟล์เดือนใหม่ก็ได้
3. Commit เข้า main → GitHub Actions แปลงข้อมูลและอัปเดต Dashboard ให้อัตโนมัติ (~1 นาที)

สคริปต์อ่าน **ทุกชีตในทุกไฟล์** ใน `data/` แล้วรวมตาม ประเภท + ชื่อ + กะ (ข้ามแถวที่ไม่มีชื่อ)
- **ประเภท** มาจากชื่อชีต เช่น `TPT A,B` → TPT, `Forklift A,B` → Forklift (ชีตชื่อ "กะ A/B" รุ่นเก่า = TPT)
- รองรับชีตที่ **วัดวันละ 2 ครั้ง** (แถว เช้า/บ่าย คั่นระหว่างวันที่ กับ บน/ล่าง/ชีพจร) และชีตที่ไม่มีคอลัมน์ทะเบียน
- หน้าแจ้งเตือน / ตารางสี / กราฟรายวัน ใช้ **ค่าที่สูงกว่าของวัน** (ไม่นับคนซ้ำ) · หน้ารายคนแสดงทั้งเช้าและบ่าย
เดือน/ปีอ่านจากหัวคอลัมน์ เช่น `วันที่ 1-30 /11/26` = พฤศจิกายน 2026

### ขั้นที่ 1 — สร้าง GitHub token (ทำบนเว็บ ครั้งเดียว)
1. เข้า GitHub → รูปโปรไฟล์ → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**
2. ตั้งชื่อ เช่น `bp-sync` · Expiration เลือกตามนโยบาย (เช่น 1 ปี — ครบแล้วต้องสร้างใหม่)
3. **Repository access → Only select repositories →** `godaresz/Dashboard`
4. **Permissions → Repository permissions → Contents: Read and write** (อย่างอื่นไม่ต้องเปิด)
5. กด Generate แล้วคัดลอก token ไว้ (จะแสดงครั้งเดียว)

### ขั้นที่ 2 — เตรียมไฟล์บนเครื่องในบริษัท
1. เปิด https://github.com/godaresz/Dashboard → ปุ่มเขียว **Code → Download ZIP**
2. แตกไฟล์ ZIP แล้วเอาโฟลเดอร์ `tools` ไปไว้ในที่ถาวร เช่น `Documents\bp-sync\`
3. ดับเบิลคลิก **`setup-token.bat`** → วาง token (คลิกขวาเพื่อวาง จะไม่เห็นตัวอักษร) → Enter
   (token ถูกเข้ารหัสด้วย Windows — ใช้ได้เฉพาะผู้ใช้นี้บนเครื่องนี้)
4. ดับเบิลคลิก **`sync-now.bat`** เพื่อทดสอบ → ควรขึ้น `อัปโหลดแล้ว …` หรือ `ไม่มีการเปลี่ยนแปลง`

### ขั้นที่ 3 — ให้ทำงานอัตโนมัติ (เลือก 1 วิธี)
| วิธี | ทำอย่างไร | หมายเหตุ |
|---|---|---|
| **A. เบื้องหลัง (แนะนำ)** | ดับเบิลคลิก `install-auto-task.bat` | ตั้ง Task Scheduler ให้รันทุก 5 นาที แม้ปิดหน้าต่าง · ยกเลิก: รัน `install-sync-task.ps1 -Uninstall` |
| **B. เปิดหน้าต่างทิ้งไว้** | ดับเบิลคลิก `auto-sync.bat` | ใช้เมื่อบริษัทไม่ให้สร้าง Scheduled Task · ปิดหน้าต่าง = หยุด · ใส่ shortcut ไว้ในโฟลเดอร์ Startup (`Win+R` → `shell:startup`) เพื่อเปิดเองตอนเปิดเครื่อง |

- เครื่องต้องเปิดอยู่และ login ผู้ใช้นั้นไว้ (ล็อกหน้าจอได้)
- ดูประวัติการทำงาน: `tools\sync.log`
- ถ้าโฟลเดอร์ถูกเปลี่ยนชื่อ สคริปต์จะหาโฟลเดอร์ใน `1.Data Cross Dock Center` ที่ชื่อมีคำว่า "วัดความดัน" ให้เอง (ถ้าเจอหลายโฟลเดอร์ ให้แก้ค่า `$Source` ช่วงบนของ `sync-from-share.ps1` ด้วย Notepad)
- ถ้าไม่มีเครื่องไหนรันได้เลย ยังอัปเดตด้วยมือได้เสมอ: เข้า GitHub → โฟลเดอร์ `data` → **Add file → Upload files** → ลากไฟล์ Excel ใส่ → Commit

สคริปต์จะเทียบไฟล์ `.xlsx` ทุกไฟล์ในโฟลเดอร์ (ไม่รวมโฟลเดอร์ย่อยและไฟล์ชั่วคราว `~$...`) กับไฟล์ใน `data/` บน GitHub
อัปโหลดเฉพาะไฟล์ที่เปลี่ยน · ไฟล์ที่ถูกลบออกจากโฟลเดอร์แชร์จะถูกลบจาก Dashboard ด้วย · อ่านได้แม้มีคนเปิดไฟล์ Excel ค้างไว้
> ⚠️ รองรับเฉพาะ `.xlsx` — ถ้าเป็น `.xls` (Excel รุ่นเก่า) ให้ Save As เป็น `.xlsx`

## รันบนเครื่องตัวเอง
```bash
pip install openpyxl
python scripts/build_data.py
python -m http.server -d site 8000   # เปิด http://localhost:8000
```

## โครงสร้าง
```
data/                 ไฟล์ Excel ต้นฉบับ
scripts/build_data.py แปลง Excel → site/data.json
site/index.html       หน้า Dashboard (Chart.js)
tools/                สคริปต์ซิงก์จากโฟลเดอร์แชร์ (PowerShell + .bat ดับเบิลคลิก, ไม่ต้องติดตั้งโปรแกรม)
.github/workflows/    Build & deploy ขึ้น GitHub Pages อัตโนมัติ
```
